Host Feedback Lifecycle Reference

Use this focused lane to review how a host app may write visible feedback into a Tom Select `error_surface: true` placeholder, then clear it after follow-up interaction. Rails Fields Kit owns the placeholder wiring and event metadata, not the message copy, retry policy, or request lifecycle UI.

Ownership boundary

  • Rails Fields Kit provides request events, operation/status metadata, and the optional `detail.surface` placeholder.
  • The host app owns visible message text, retry actions, reveal timing, escalation copy, analytics, and business-specific recovery guidance.
  • This artifact does not add default visible error copy, built-in retry UI, loading UI, request execution behavior, or production CSS.

Review checklist

  • Confirm host-owned feedback is visually close to the field but not mistaken for built-in Rails Fields Kit copy.
  • Confirm the clearing state is explained as a follow-up interaction response, not as a request lifecycle guarantee.
  • Confirm event names wrap cleanly on narrow viewports and remain readable without relying on color alone.
  • Keep detailed request behavior and event payload contracts in the events guide.

Scope note. This page is a static visual aid for design review. The maintained contract for Tom Select request events and `detail.surface` remains in `doc/events.md` and the runtime code.
