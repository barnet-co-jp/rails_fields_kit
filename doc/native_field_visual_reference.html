Non-editable states

Disabled and readonly stay in the same wrapper lane

Both states still belong to the native helper family, but they split responsibilities: disabled communicates unavailability, while readonly keeps the current value legible without offering an editing affordance.

Accessibility boundary

Shared wiring versus host-app opt-out

`accessibility: false` removes the shared automatic aria wiring, but it does not remove the wrapped native helper lane itself.

Shared default Hint and error ids feed `aria-describedby` automatically. `aria-invalid` and `aria-required` reflect the wrapper state.
`accessibility: false` The host app owns aria wiring explicitly. Label, hint, affixes, and validation redisplay still stay in the same visual lane.
