Suggested review flow

Keep the artifact review small and evidence-driven so it does not drift into implementation or proposal review.

  1. Choose the lane that matches the current PR, release gate, or design question.
  2. Open the individual static HTML reference and compare desktop and narrow viewport readability.
  3. Record release or PR evidence in sample_app_results.md when the artifact changes or gates a release.
  4. Update visual_references.md and this index when a new visual reference lands on main.

Scope note. This page is a static index for documentation artifacts. It does not define public helper behavior, JavaScript exports, request lifecycle events, or runtime rendering contracts.
