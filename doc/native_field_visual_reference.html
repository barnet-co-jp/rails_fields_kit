Input metadata and constraints

Metadata and constraint attributes stay native

Native helper lanes can expose ordinary browser attributes such as `inputmode`, `autocomplete`, `maxlength`, and `pattern` without adding masks or owning browser validation message policy.

`rfk_money_field` `inputmode="decimal"` with optional prefix or suffix copy.
`rfk_percent_field` `inputmode="decimal"` while the `%` suffix remains visual context.
`rfk_phone_field` `autocomplete="tel"` for the browser's native telephone autofill lane.
`maxlength` Host apps may pass length constraints through; helper copy should explain limits instead of implying bundled counters.
`pattern` Pattern shape is native input metadata. Browser validation wording, masking, and normalization stay host-app owned.
Reference-only lane: documents native attribute pass-through without changing production markup or validation behavior.

Accessibility boundary

Shared wiring versus host-app opt-out

`accessibility: false` removes shared automatic aria wiring, but it does not remove the wrapped native helper lane itself.

Shared default Hint and error ids feed `aria-describedby` automatically. `aria-invalid` and `aria-required` reflect the wrapper state.
`accessibility: false` The host app owns aria wiring explicitly. Label, hint, affixes, and validation redisplay still stay in the same visual lane.
Internal note
Handled by the host app's accessibility helper.
