Accessibility boundary

Shared wiring versus host-app opt-out

`accessibility: false` removes shared automatic aria wiring, but it does not remove the wrapped native helper lane itself.

Shared default Hint and error ids feed `aria-describedby` automatically. `aria-invalid` and `aria-required` reflect the wrapper state.
`accessibility: false` The host app owns aria wiring explicitly. Label, hint, affixes, and validation redisplay still stay in the same visual lane.

Generated id wiring

Repeated and custom-id previews stay explicit

When a host app renders the same object and method more than once, this lane keeps the current generated ids visible without introducing a new helper option or runtime behavior.

Current generated lane `customer_support_email_hint` `customer_support_email_error` `aria-describedby` points at the generated hint and error ids.
Repeated or custom `id:` lane Host apps should check duplicate ids when the same field appears twice. Custom input ids do not automatically rename generated hint or error ids.
