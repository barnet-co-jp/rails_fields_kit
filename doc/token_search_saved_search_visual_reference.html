Viewport QA checklist

Use this checklist when reviewing the saved-search token state across desktop and narrow viewports.

  • Desktop: saved-search options remain visually comparable with field and value options while the left edge accent and `kind: saved search` label are easy to scan.
  • Narrow viewport: long option titles, saved-search token values, multi-token selections, remove affordances, and helper copy wrap inside the dropdown without clipping the badge, token, or card boundary.
  • Density: the fixed hero size, plain-case chips, and unexpanded letter spacing keep the state-comparison cards ahead of decorative heading treatment.
  • Delimiter reading: the space-delimited multi-token state remains readable without implying that Rails Fields Kit owns token parsing or query execution.
  • Kind reading: saved, field, value, and free-text suggestions can be distinguished by visible text and layout, not color alone.
  • Boundary: the examples continue to show Rails Fields Kit rendering suggestion metadata while parsing, saved-search execution, storage, and authorization stay with the host app.
Scope note. This page is a static visual aid for saved-search suggestion options and space-delimited token wrapping. Rails Fields Kit only builds and renders suggestion JSON; saved-search storage, authorization, parsing, and execution remain host-app responsibilities.
