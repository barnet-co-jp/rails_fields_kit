Dropdown Parent Review Lane

Use this companion artifact to discuss how `dropdown_parent:` reads in modal, drawer, and document-level dropdown review without treating overlay layout, focus policy, z-index, portal behavior, or production CSS as Rails Fields Kit responsibilities.

Dropdown parent guide Release evidence lane Visual reference map Tom Select option docs
What Rails Fields Kit owns Rendering the selector string into Tom Select config as `dropdownParent` when `dropdown_parent:` is provided.
What the host app owns The target element, overlay DOM, clipping context, focus trap, z-index, viewport constraints, and CSS.
What this artifact checks Whether reviewers can distinguish modal, drawer, and body-mounted dropdown review lanes at desktop and narrow widths.

Responsibility boundary

Use this table when review feedback starts to drift from selector pass-through into overlay implementation.

Ownership table

Concern Rails Fields Kit Host app
Selector Renders the configured string as Tom Select `dropdownParent`. Chooses a valid selector for the current page.
Target element Does not create or resolve modal, drawer, or portal DOM. Provides the target and keeps it stable.
Overlay behavior No z-index, focus trap, positioning, clipping, or CSS policy. Owns layout, stacking, focus policy, and browser evidence.

Reviewer checklist

  • Can the reviewer tell which selector target each lane represents?
  • Does the copy avoid promising modal or drawer behavior from the gem?
  • Do tags, code lines, and dropdown examples wrap cleanly near 390px width?
  • Is any browser positioning approval recorded separately from this static artifact?

Scope note. This static artifact is a review aid for `dropdown_parent:` selector pass-through. It does not change FormBuilder behavior, Stimulus values, Tom Select option handling, production CSS, portal implementation, focus management, screenshot approval CI, or sample app execution.
